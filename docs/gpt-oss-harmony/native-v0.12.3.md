# Native Windows v0.12.3 candidate

Baseline: deployed Harmony commit `0c636ef06f6d1f77696320f79a1a736864db9f6d`.
Upstream: tag `v0.12.3`, commit `91ea4e3421d1d8069f13d4a463fcb5986d94ea60`.
The original dirty workspace and installed v0.12.0 runtime are preserved.

Use `upgrade.py --build-native --node-directory <Node22-directory> --frontend-baseline <deployed-frontend>` from this prepared candidate. This explicit path invokes `build_native.py`; it does not invoke a container runtime or control services. Python must be 3.11.13, Node must be 22.23.3. Prepare `build` and `hatchling` in a separate Python build environment first. `--dependencies-only` installs the npm lockfile and caches Pyodide dependencies before an outage. The builder carries forward public browser telemetry metadata in process memory, uses an 8192 MiB Node heap, verifies crypto, builds the frontend, and packages the verified frontend into the wheel without rerunning the Hatch frontend hook. `dist/native-build.json` binds the wheel checksum, source revision, npm lockfile, and build dependency versions. Install the custom wheel into a fresh runtime with copied dependencies, never over the active runtime.

`verify_crypto_windows.py --apply --node <node.exe>` is a one-time portability operation on pristine pinned inputs. It independently checks git blobs and every vendor hash, changes filesystem root decoding and POSIX logical paths, then changes only the source fingerprint. Subsequent checks omit `--apply`. Vendor binaries, checksums, and other manifest fields stay unchanged. The check also exercises paths with spaces and rejects altered source/artifacts in disposable fixtures.

`Build-Outage.ps1` requires elevation and both original services running. It waits for existing generations, stops OpenWebUI then GPTOSS20B, and requires 10 GiB available commit. The build deadline is nine minutes from the beginning of the outage, reserving six minutes of the 15-minute budget for restoration. Timeout kills the owned build process tree. Every exit restores GPTOSS20B, waits up to 180 seconds for model health, then starts the original OpenWebUI and verifies v0.12.0. Evidence is written to a unique run directory beside the candidate; evidence-write failures cannot bypass restoration. Caddy is untouched.

Build success is not deployment acceptance. Qualify the installed candidate on loopback 3003 with disposable data/static directories, matching database counts/authentication/assets, migrations, provider-key nonpersistence, native Socket.IO execution/continuation/citations, ECharts, offline embeddings, and actual browser monitoring traffic. Only then prepare a wheel-hash-bound elevated cutover. Drain generations, stop only OpenWebUI, snapshot complete current data, launchers, and manifest, and switch its existing launcher. Acceptance failure restores the matching previous data/runtime/launchers/manifest together. Keep rollback artifacts. No new service, proxy change, feature enablement, secret rotation, or reboot is part of this update.
